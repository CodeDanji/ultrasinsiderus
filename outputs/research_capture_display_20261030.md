# 고정 카메라·체성분·표시 도구 보충 조사

조사일: 2026-10-30. 공식 저장소·문서 확인에 따른 조사이며 설치·촬영·추론 실행 결과가 아니다.

## 1. 카메라와 3D 처리·표시

| 도구 | 실제 역할 | 입력 → 출력 | 라이선스·도입 판단 |
|---|---|---|---|
| [OpenCV](https://opencv.org/license/) | 카메라 제어, 왜곡 보정, 보정판 검출, 다중 시점 처리의 기반 | 카메라 영상·보정판 → 보정값·영상 | 4.5 이상 Apache-2.0. Windows 사용 가능. 학습 모델 없이 촬영 기반 구성 가능. 카메라를 여러 개 연결할 때 장치별 드라이버·동시 연결·USB 대역폭은 실물 확인 필요 |
| [Caliscope](https://github.com/mprib/caliscope) | 고정 카메라 배열의 내부·외부 파라미터 보정 | 보정 영상 → camera_array.toml 등 | BSD-2-Clause. GUI/API. 카메라가 모두 같은 보정판을 동시에 볼 필요 없이 겹치는 카메라 관계를 이어 보정할 수 있음. 내부 인체를 생성하는 도구가 아님 |
| [AquaCal](https://github.com/McGrathLab/AquaCal) | 물 경계를 보는 카메라의 굴절 보정 | ChArUco 관측·설정 → calibration.json | MIT. 평평한 수면을 통해 물속을 보는 공기 중 카메라에 초점. 통의 곡면 벽·두꺼운 창·물결·침수 하우징에 바로 적용 가능하다는 증거는 없음. 적용 형상을 먼저 확인해야 함 |
| [Open3D](https://github.com/isl-org/Open3D) | 점군·메시 정렬, 정리, 표면 재구성·렌더링 | 점군/메시 → 정리된 3D 자료 | [MIT](https://github.com/isl-org/Open3D/blob/main/LICENSE). 이미 얻은 기하 데이터의 처리에 유용. 사진만 넣으면 내부가 나오는 모델은 아님 |
| [Three.js](https://github.com/mrdoob/three.js) | 브라우저의 회전·확대·레이어·단면 표시 | 메시/재질 → 인터랙티브 화면 | MIT. 생성이나 해부학 추정 기능은 직접 제공하지 않음. GLB/glTF로 정리된 모델을 보여주는 최종 화면 후보. 사용 자산 라이선스는 별도 |

OpenCV [다중 카메라 보정 문서](https://docs.opencv.org/4.13.0/d2/d1c/tutorial_multi_camera_main.html)는 실제 보정판 크기와 카메라 간 공유 관측을 사용한다. 임의로 놓은 카메라 여러 대의 사진이 저절로 실제 크기의 3D를 보장하지는 않는다.

## 2. 체성분 관련 후보와 제외 이유

| 후보 | 확인한 것 | 현재 프로젝트와의 간극 |
|---|---|---|
| [DigitalScale](https://github.com/im-ethz/DigitalScale) | 전신 스마트폰 이미지로 BMI를 추정하는 연구 코드·모바일 흐름 | BMI는 체지방률·골격근량·내장 상태가 아님. 발/하퇴 사진에 대한 검증이 아님. 학습 데이터는 proprietary라고 명시. 확인한 루트에 일반 LICENSE가 보이지 않아 공개 코드만 보고 상업 이용 가능으로 판정하지 않음. 가중치 제공 범위와 권한도 별도 확인 필요 |
| [Pose-independent 3D Anthropometry](https://github.com/DavidBoja/pose-independent-anthropometry) | 70개 신체 랜드마크에서 11개 신체 치수 추정. SMPL 모델 다운로드 필요 | 체성분이 아니라 외형 치수. 발/하퇴만으로 전신 입력을 충족하지 못함. 코드 라이선스 명확성 및 SMPL 자산 조건이 별도이므로 기본 상업 도입 후보에서 보류 |
| [Google Research PhotoScan](https://www.research.google/blog/seeing-beyond-bmi-estimating-cardiometabolic-risk-with-smartphone-imagery/) | 사진·개인 특성과 DXA 기준 학습으로 체성분을 추정하는 연구 소개 | 연구 존재는 참고 가치가 있으나, 확인한 소개만으로 재사용 가능한 코드·가중치·상업 라이선스 세트를 확보한 것은 아님. 족욕기 부분 촬영에서 같은 결과가 난다는 근거 없음 |
| [Comp2Comp](https://github.com/StanfordMIMI/Comp2Comp) | CT 기반 체성분 분석 코드. Apache-2.0 | 카메라 사진을 CT로 바꾸는 도구가 아님. CT가 있을 때 쓰는 별도 경로. 모델과 의존 자료의 조건은 개별 확인 |

따라서 현재 조사에서는 **발/하퇴의 저가 RGB 사진만으로 체지방률·골격근량·내부 분포를 신뢰성 있게 제공하는 즉시 도입 가능한 오픈소스 패키지**를 확인하지 못했다. 전신 사진 기반 추정 연구 자체가 없다는 뜻은 아니다.

## 3. 카메라 성능에 대한 판단

아래는 제품 실험 전의 설계 판단이다. 특정 카메라 구매 추천이나 보장 사양이 아니다.

- 사진을 단순한 생성 참고로 쓰면 높은 해상도보다 윤곽이 분명하고 초점이 맞는 입력이 중요할 수 있다.
- 사진과 닮은 실제 표면 3D를 복원하려면 겹치는 시야, 안정적인 초점·노출·조명, 렌즈 보정, 움직임 제어가 중요하다. 생성으로 빈틈을 메우는 것과 복원 정확도는 따로 평가한다.
- 저가 카메라라도 **실제 통 안 촬영 거리에서 초점이 맞는가**가 먼저다. 자동 초점이 계속 바뀌거나 카메라별 색·노출이 다르면 입력 일관성이 나빠질 수 있다.
- 카메라 여러 대가 추가 시야를 주지만, 탱크 벽이나 발끼리의 가림을 없애지는 않는다. 바닥에 닿은 발바닥은 보이지 않을 수 있다.
- 물과 투명 창을 통과하면 굴절이 생긴다. [GEOMAR 보정 설명](https://www.geomar.de/en/cameracalibration), [CVPR 2013 원논문](https://www.cv-foundation.org/openaccess/content_cvpr_2013/html/Yau_Underwater_Camera_Calibration_2013_CVPR_paper.html). 공기 중 보정이 그대로 수중 정밀 복원을 보장하지 않는다.
- 생성 중심의 경우 여러 카메라를 쓰지 않는 단일 사진 모델도 비교해야 한다. 카메라 수를 늘린 비용이 실제 결과 개선에 기여하는지 확인할 필요가 있다.

## 4. 권장 비교 실험 — 아직 수행하지 않음

1. 같은 발/하퇴를 건조 조건에서 여러 각도로 촬영한 작은 입력 묶음을 확보한다. 특정 고정 배열이 확정되기 전에는 휴대폰 사진으로 후보를 거를 수 있다.
2. 같은 입력으로 생성형 3D와 다중 시점 복원을 비교한다. 발가락 개수, 좌우, 발목 연결, 원본 유사성, 회전 시 깨짐을 확인한다.
3. 선택한 해부학 자산을 수작업으로 한 번 맞춰 본다. 내부 모델의 품질 문제와 외형 복원 문제를 분리한다.
4. 저가 카메라 1대의 실물 사진으로 같은 결과가 유지되는지 비교한 후 다중 구매를 결정한다.
5. 고정 배열에서 사람의 미세한 움직임·가림·재촬영을 시험한다. 정밀 복원 경로는 보정 전후도 비교한다.
6. 마지막으로 물·창·조명 조건을 넣어 차이를 확인한다. 생성 대기시간·메모리·총 운영시간은 해당 장비에서 측정한다.

기록할 값: 사용 모델·가중치 버전·입력 수·전처리·해상도·장비·VRAM·생성 시간·실패 수/전체 수·원본과 다른 구조·수작업 보정시간. 예쁜 성공 사례 하나로 자동 운영 가능을 판정하지 않는다.
