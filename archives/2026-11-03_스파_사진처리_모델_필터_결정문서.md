# 스파 사진 처리 — 모델·필터 결정 문서

> 이력 보관본. 2026-11-03부터 [스파 내부 모형 이미지 생성 PRD](../스파_내부모형_이미지생성_PRD.md)가 이 문서를 대체한다. 아래 기술 채택 판단은 현행 기준이 아니다.

작성: 2026-10-30 · 상태: **1차 기술 선택안. 실행 검증 전**

이 문서는 후보 목록을 늘리는 조사서가 아니라, 첫 시제품에서 무엇을 쓰고 무엇을 빼는지 정하는 문서다. 사용자 승인된 완제품 사양이나 성능 검증 결과를 뜻하지 않는다. 문서 작성만 수행했으며 모델 설치·사진 처리·기기 제작은 수행하지 않았다.

## 1. 결정 요약

**OpenCV 전처리 → rembg/U²-Net 외형 분할 → 사진의 윤곽에 표준 해부학 템플릿 자동 정렬 → Blender 자동 렌더링**을 첫 구현안으로 선택한다. 사진을 무조건 고화질화하거나 사진마다 내부를 독립 생성하지 않는다.

내부는 BodyParts3D 공식 배포 모델을 재료로 사용한다. 사진에 맞춰 위치·크기·외형 비율을 조정하고, 동일 3D에서 레이어와 단면을 렌더링한다. 개인의 내부를 사진에서 복원하는 AI는 이번 채택 목록에 없다. **표준 내부 모델의 자동 개인화 연출**이 선택안이다.

화질 개선은 **Real-ESRGAN `realesr-general-x4v3`를 선택 옵션**으로 둔다. 기본값은 끔이다. 표면 비율을 얻는 작업에는 원본을 사용하며, 표시 품질이 실제로 개선될 때만 보정본을 쓴다.

| 단계 | 선택 | 적용 상태 |
|---|---|---|
| 촬영 품질 확인·렌즈 보정·색 맞춤 | OpenCV | 기본 채택. 수중 보정의 유효 범위는 실물 확인 필요 |
| 배경 제거·외형 마스크 | rembg, 세션 `u2net` | 첫 분할 모델로 채택. 물속 발 사진 성능 검증 필요 |
| 저화질 개선 | Real-ESRGAN `realesr-general-x4v3`, 출력 2배부터 비교 | 선택 기능. 기본 처리의 필수 의존성에서 제외 |
| 내부 해부학 재료 | BodyParts3D 공식 아카이브 배포본 | 채택. 부위별 파일·레이어 확인 필요 |
| 외형·내부 템플릿 정렬 | OpenCV + SciPy 기반 제한된 파라미터 탐색 | **새로 개발할 연결 기능**, 기성 모델 기능이 아님 |
| 3D 정리·레이어·단면·출력 | Blender 스크립트, GLB/PNG/MP4 | 채택. 템플릿 준비는 초기 1회 작업 |
| 일반 이미지→3D 생성 | TripoSR / TRELLIS | 첫 운영 경로에서는 보류 |

## 2. 결정의 기준과 최신 사용자 조건

- 목표: 미래 초음파 기기를 스파 안에서 이용하는 경험의 수요를 검증한다.
- 물이 들어간 기존 스파기기/족욕기에 저가 고정 카메라 약 4대를 부착한다. 카메라 단품 대신 설치 구조 전체의 방수를 확보할 수도 있다.
- 고화질보다 외형 구조·비율이 우선이다. 화질 개선 오픈소스를 검토한다.
- 뼈·혈관·지방·근육 등을 보고 싶으며, 가능하면 단면과 회전 가능한 3D를 제공한다.
- **사용자 확인: 1~2분 안에 완성할 필요는 없고, 수작업은 최대한 피한다.** 따라서 한 명씩 마스크를 그리거나 모델을 수동 정렬하는 방식을 정상 운영으로 삼지 않는다.

대기시간의 최종 상한은 미정이다. 당일 스파 이용 중 결과를 전달하는 방식을 우선 가정하되, ‘실시간’ 성능을 약속하지 않는다. 초기 템플릿 제작·장치 보정 작업과 이용자마다 반복하는 작업을 분리한다.

## 3. 세 가지 접근을 비교한 이유

| 접근 | 강점 | 이번에 선택하지 않거나 선택하는 이유 |
|---|---|---|
| 사진을 각각 내부 이미지로 생성한 뒤 3D로 합침 | 이미지 한 장의 표현 자유도가 높음 | 시점마다 뼈·혈관 위치가 달라질 수 있고, 여러 2D를 하나의 일관된 3D로 만드는 추가 문제가 생김. 보류 |
| TripoSR/TRELLIS로 외형 3D를 만든 뒤 내부를 맞춤 | 사진 기반 외형 생성의 자동화 가능 | 외형 생성 뒤 내부 정렬은 여전히 필요. 발가락·뒤쪽 오류, GPU·설치 부담이 추가됨. 비교 실험으로 보류 |
| 외형 윤곽으로 준비된 해부학 템플릿 자동 정렬 | 내부 연결과 레이어가 일관되고, 초기 제작 뒤 반복 자동화하기 쉬움 | **채택**. 상세한 개인 외형 재현보다 안정적인 체험·자동화에 우선순위를 둠. 정렬 기능 개발과 자세 제한이 필요 |

정교한 개인 외형 재현이 고객 선택에 필수라고 확인되면 두 번째 경로를 다시 연다. 현재는 개인별 미세 해부학을 재현하려고 생성 모델을 늘리지 않는다.

## 4. 처리 흐름과 네 장의 사진이 하는 일

1. 카메라 ID·촬영 시각·장치 설정과 함께 원본 네 장을 보존한다.
2. 흔들림, 잘림, 큰 반사·기포·결로로 윤곽이 사라진 입력을 거른다. 임계값은 실제 촬영 세트로 정한다.
3. 검증된 장치별 보정만 적용하고, 촬영 영역을 잘라낸다.
4. `rembg/u2net`으로 외형 마스크를 만든다. 사진별 마스크를 별도 저장한다.
5. 네 시점에서 외형 길이·폭·방향과 실루엣을 함께 비교해 템플릿 위치·크기·방향을 찾는다.
6. 외형과 내부 레이어에 같은 변환을 적용한다. 내부 조직을 사진마다 따로 생성하지 않는다.
7. 템플릿에서 뼈·근육 등 레이어, 단면 이미지, 회전 영상과 GLB를 자동 출력한다.
8. 결과 품질 기준에 실패하면 재촬영 또는 실패 상태로 보낸다. 수동 보정 후 성공으로 기록하지 않는다.

네 사진은 같은 사람의 다른 방향에서 보이는 외형을 제약한다. 네 장의 단면을 측정하는 것이 아니며, 네 장이면 모든 면이 복원된다고 가정하지 않는다. 가려진 발바닥·발가락 사이와 내부 해부학은 템플릿에서 오는 부분이다.

## 5. 전처리·필터의 기본값

| 처리 | 기본값 | 이유와 적용 조건 |
|---|---|---|
| 렌즈 왜곡·수중 촬영 보정 | 장치별 검증 후 사용 | 실제 물·창·렌즈 조합에서 기준 물체로 확인. 공기 중 보정값 재사용을 보장하지 않음 |
| 크롭 | 고정 ROI 사용 | 스파 벽·케이블·반사를 줄임. 좌표와 크롭 범위를 기록 |
| 색·밝기 | 촬영 시 고정, 필요 시 카메라별 동일 기준 보정 | 사진마다 자동 보정 강도가 달라지지 않게 함 |
| 노이즈 제거·샤프닝 | 기본 끔 | 윤곽 변형을 피하고 필요성이 확인될 때만 추가 |
| CLAHE·강한 대비·HDR 스타일 | 기본 끔 | 물·기포·피부 반사 강조를 피함. 내부 구조를 얻는 기능이 아님 |
| 업스케일링 | 기본 끔, 표시용 후보만 2배 비교 | 고화질화가 분할·정렬 성능을 높인다는 가정을 두지 않음 |
| 마스크 정리 | 작은 잡영 제거만 조건부 | 발가락 사이를 메우는 큰 closing·일괄 구멍 채우기는 사용하지 않음 |
| 구조를 새로 그리는 image-to-image 필터 | 운영 경로 제외 | 시점 간 일관성과 결과 재현성 유지 |

입력 해상도는 480p·720p·1080p 비교로 결정한다. 같은 사진의 축소본 비교는 모델의 해상도 민감도를 보는 실험이고, 실제 저가 카메라의 센서·압축·초점 성능 검증을 대신하지 않는다. 특정 해상도 구매를 먼저 확정하지 않는다.

## 6. 모델별 선택 이유와 주의점

### rembg + U²-Net

배경 제거를 위한 첫 모델을 `u2net`으로 고정한다. CPU ONNX Runtime 경로부터 시작할 수 있어 첫 기본안에 별도 생성용 GPU 구매를 요구하지 않는다. 모델 파일을 준비한 뒤 로컬에서 처리하는 방향이다. 물속 신체 사진 전용 모델이 아니므로 수면 반사나 발가락을 잘못 분리할 수 있다.

분할이 실패하면 운영자가 사진을 매번 고치는 대신 배경·조명·촬영 자세를 먼저 수정한다. 첫 검증에서 실패가 반복되면 모델 선택을 재검토한다. 초기 평가용 수동 정답 마스크 제작은 허용하되 사용자 운영 단계의 필수 작업으로 넘기지 않는다.

rembg 코드는 MIT, 원 U²-Net 저장소는 Apache-2.0이다. **rembg 코드 라이선스만으로 모든 다운로드 모델의 이용조건이 같다고 보지 않는다.** 실제 사용할 ONNX 파일의 배포 출처·버전·해시와 이용조건 확인을 구현 착수 조건으로 둔다. 분할 성능·현재 PC 호환성은 아직 미검증이다. [rembg](https://github.com/danielgatis/rembg), [U²-Net](https://github.com/xuebinqin/U-2-Net), [사용 세션 코드](https://github.com/danielgatis/rembg/blob/main/rembg/sessions/u2net.py)

### Real-ESRGAN — `realesr-general-x4v3`

공식 모델 목록에서 메모리·시간 부담을 줄인 범용 이미지 모델로 소개된 후보를 고른다. 선택 시 출력 2배부터 비교한다. 애니메이션용·얼굴 전용 복원 모델은 쓰지 않는다. 적용하지 않은 원본 대비 표시 품질에 이득이 없으면 기능 자체를 뺀다.

크게 흐리거나 가려진 입력을 정상 촬영으로 바꾸는 구제 수단으로 사용하지 않는다. 처음에는 정렬용과 분리하며, 보정본을 모델 입력으로 쓰는 것은 별도 비교에서 이득이 확인될 때만 허용한다. 공식 코드는 BSD-3-Clause이고, 정확한 배포 가중치와 실행 패키지는 구현 시 고정한다. [공식 저장소](https://github.com/xinntao/Real-ESRGAN), [모델 목록](https://github.com/xinntao/Real-ESRGAN/blob/master/docs/model_zoo.md)

### BodyParts3D + Blender

내부의 뼈·근육·혈관 후보는 일반 해부학 데이터를 사용한다. 공식 아카이브는 OBJ 배포와 CC BY 4.0 이용허락을 안내한다. 과거 미러·파생본의 조건과 섞지 않는다. 첫 준비 단계에서 실제 필요한 발/하퇴 부위의 메시와 품질을 열어 확인한다. 이 문서 작성에서는 파일을 내려받아 확인하지 않았다. [다운로드](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html), [이용허락](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)

외형 껍질과 내부 메시를 초기 1회 같은 좌표계에서 조립하고, 재질·조명·레이어 이름·출력 카메라를 템플릿으로 저장한다. 이용자마다 조립하지 않는다. Blender 스크립트가 정렬 결과를 읽어 출력을 만드는 기능은 이후 개발 범위다.

## 7. 자동 정렬은 별도 개발 기능이다

사진에서 원하는 내부를 바로 만들어주는 기성 모델을 찾았다는 결론이 아니다. 재사용 템플릿과 사진을 연결하는 작은 정렬 프로그램이 필요하다.

첫 실험은 **한쪽 발·발목의 고정 자세**를 작업 가정으로 둔다. 최종 고객 부위를 확정한 것은 아니다. 자유롭게 움직이는 양발·관절 자세까지 한 번에 자동화하지 않는다.

- 장치별 카메라 위치·방향·보정값을 초기 설정한다. 전체 촬영 조합에서 검증한다.
- 템플릿의 길이·폭·높이 배율, 위치, 제한된 방향만 조정한다. 자유로운 관절·개별 발가락 변형은 첫 범위에서 뺀다.
- 각 카메라에 투영한 템플릿 실루엣과 사진 마스크의 차이를 네 시점 전체로 줄인다. 무리한 변형을 제한한다.
- 첫 최적화 후보는 `SciPy optimize.minimize(method='Powell')`다. 이 함수가 정렬 기능을 제공하는 것은 아니며 투영·오차함수·탐색범위를 만들어야 한다. [공식 함수 문서](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-powell.html)
- 사진 해상도나 표시용 모델과 달리, 미리 단순화한 외형 메시를 정렬에 사용해 처리 부담을 줄인다.

외형 비율에 맞춰 전체 해부학 세트를 함께 변환하므로, 내부 뼈·혈관의 실제 개인차를 반영하지 않는다. 길이·폭의 절대 cm 값도 수중 기준물 검증을 통과하기 전에는 결과 수치로 표시하지 않는다. 단순 핀홀 보정이 수중 전 범위에서 충분하다는 가정을 하지 않는다. 기준물의 위치별 오차가 크면 촬영 범위를 제한하거나 별도 굴절 보정을 검토한다. [OpenCV 보정 원리](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html)

이 자동 정렬이 실물에서 성립하는지 확인하기 전에는 전체 체험 자동화를 완료했다고 보지 않는다.

## 8. 보여줄 결과물의 범위

| 결과물 | 첫 범위 | 채택 조건 |
|---|---|---|
| 외형 | 사진 윤곽·비율에 맞춘 템플릿 | 네 시점 정렬 검사 통과 |
| 뼈·근육 | 표준 모델 레이어 | 필요한 파일과 메시 품질 확인 |
| 혈관 | 표준 모델의 제공 부위만 | 작은 구조가 실제 화면에서 읽히는지 확인 후 포함 |
| 지방 | 보류된 확장 레이어 | 적절한 원본 존재 또는 별도 제작 범위 확인. 피부와 근육의 간격을 개인 지방량으로 해석하지 않음 |
| 단면 | 같은 3D의 단면 렌더링 | 절단면이 비거나 조직이 누락되지 않는 템플릿 구성 필요 |
| 회전·확대 | GLB 모델, 보조 MP4 | 뼈·근육 등 레이어가 분리된 형태로 출력 |
| 체지방률·근육량·이상 판정 | 첫 범위 제외 | 사진과 표준 내부 모델에서 검증된 산출 경로를 확보하지 못함 |

표면 메시를 잘라 보여주는 것만으로 채워진 조직 단면이 완성되지는 않는다. 모델의 닫힌 형상·절단면 채우기·조직별 재질은 템플릿 제작 시 준비한다. 화려한 단면을 만들기 위해 조직을 임의로 늘리는 대신, 준비된 레이어 범위를 명시한다.

체험 설명에는 ‘실제 초음파 검사 결과가 아닌, 외형 정보를 활용한 내부 구조 시뮬레이션’이라는 의미를 전달한다. 해당 설명 후에도 남는 선택·예약·지불 행동과 미래 실제 측정기기에 대한 기대를 구분해 기록한다. 이 구분이 있어야 초음파 기기 수요에 대해 무엇을 배웠는지 설명할 수 있다.

## 9. 보류·제외 항목과 다시 검토할 조건

| 항목 | 현재 결정 | 다시 검토할 조건 |
|---|---|---|
| TripoSR | 운영 경로 보류 | 표준 외형의 개인화가 부족하고 생성 메시가 실제로 개선될 때. 단일 사진 모델이므로 네 장을 융합한다고 가정하지 않음 |
| TRELLIS | 운영 경로 보류 | 실제 사진의 다중 시점 생성이 템플릿보다 유리하고 GPU 환경이 확보될 때 |
| COLMAP | 초기 경로 제외 | 촬영 시점을 늘리고 중첩·텍스처를 확보해 표면 재구성이 필요해질 때 |
| Hunyuan3D-2 | 해당 버전 한국 기본 사용안 제외 | 한국에 적용 가능한 별도 이용조건이 확보될 때 |
| 수동 GrabCut·매번 브러시 수정 | 정상 운영 제외 | 평가용 정답 마스크·문제 진단에 한정 |
| 물 제거·반사 제거 생성 모델 | 기본 제외 | 물속 입력에서 윤곽을 보존하며 이득을 보이는 별도 검증 후 |
| 사진마다 내부 2D 생성 후 적층 | 제외 | 시점·단면 간 구조 일관성을 유지하는 방법이 입증될 때 |

기존 모델별 환경·라이선스 조사는 [기기·오픈소스 조사](../스파_건강시각화_기기스펙_및_오픈소스_조사.md)를 참고한다. 이번 기본 경로는 TripoSR의 약 6GB 또는 TRELLIS의 16GB VRAM을 필수 요구로 승계하지 않는다. Blender 렌더링과 분할의 실제 처리시간은 보유 PC에서 확인한다.

## 10. 첫 검증과 채택을 유지할 기준

아래 숫자는 성능 사실이 아닌 **첫 내부 시험의 판정안**이다. 고객 수요 검증이나 의료 정확도 검증을 대체하지 않는다.

1. 템플릿 한 개에서 뼈·근육 레이어, 단면 이미지, GLB가 실제로 출력되는지 먼저 확인한다. 혈관·지방은 별도 제공 여부를 기록한다.
2. 실제 물·하우징·네 카메라 조합에서 기준물과 동일 부위 반복 촬영을 한다. 가림·반사·굴절 오차를 확인한다.
3. 3명 × 2회, 총 6세트의 내부 시험을 한다. 초기 정답 확인용 마스크만 사람이 준비해 자동 분할·정렬을 비교한다.
4. 해상도 비교는 자동 분할·정렬에 필요한 최저 입력을 고르는 데 사용한다. 전 시점에서 주요 윤곽이 유지되는지 본다.
5. **6세트 중 최소 5세트가 운영자 마스크 수정·3D 수정 없이 최종 출력까지 완료**되는 것을 첫 자동화 목표로 둔다. 재촬영과 오류도 따로 기록하며, 수정한 성공을 무수정 성공으로 세지 않는다.
6. 마스크와 투영 윤곽 비교에는 IoU를 쓰되 발가락 잘림·좌우 뒤집힘·내부 메시 돌출을 별도 검사한다. 첫 시험의 시작 기준은 각 유효 시점 IoU 0.85 이상으로 두고, 실제 실패와 맞는지 확인 후 고정한다. 이 값은 해부학 정확도의 기준이 아니다.
7. 원본·선택 업스케일본을 나란히 비교한다. 처리시간만 늘고 품질이 같으면 업스케일 기능을 빼고 진행한다.
8. 촬영·분할·정렬·렌더링 시간, 총 대기시간과 이용자별 수작업 시간을 기록한다. 목표는 이용자별 편집 0분이며 실제 달성 여부를 보고한다. 처리시간 상한은 스파 운영시간을 정한 뒤 확정한다.

실패하면 무거운 생성 모델을 바로 추가하기보다 촬영 환경 → 마스크 → 자세·템플릿 → 정렬 순서로 원인을 좁힌다. 자동화가 성립하지 않으면 모델 선택을 다시 열고, 수작업을 필수 운영으로 몰래 추가하지 않는다.

## 11. 다음 단계와 문서 검토 결과

다음 작업은 모델을 모두 설치하는 것이 아니라 **BodyParts3D 부위 확인·기준 템플릿 1개·자동 마스크의 실제 입력 검증**이다. 이 문서는 구현 지시서 전체를 대신하지 않으며, 이후 코딩 전에는 위 범위의 작은 구현 계획을 작성한다.

- 검토 결론: 문서 작성 진행. 물 필수·약 4대·낮은 화질 허용·수작업 최소화 조건을 반영했다.
- 핵심 미검증: 물속 입력 분할과 제한된 템플릿 자동 정렬, 내부 메시의 단면 품질.
- 초기 1회 인력: 장치 보정, 해부학 모델 정리, 재질·단면 템플릿 제작은 필요하다.
- 반복 운영: 촬영 시작·결과 확인·필요 시 재촬영을 제외한 편집을 기본 요구로 두지 않는다.
- 저장 위치: 이 문서와 기존 맥락·조사 문서 모두 같은 `린` 폴더.
- 실행 위치: 아직 프로그램·서비스·모델 실행 환경을 만들지 않았다.
- 브랜치·푸시: 현재 폴더는 Git 저장소가 아니므로 해당 없음.
