# 실행 검증 기록 — 2026-11-06

## 환경

- Linux x86_64, Python 3.12.14, Blender 4.3.2 CPU.
- 이 저장소의 `runtime/.venv`를 새로 만들고 **system site packages를 사용하지 않고** `requirements.txt`와 `constraints-linux-py312.txt`로 설치했다.
- `run.py check`: Python 모듈·Blender 버전·실제 ONNX/GLB 3개 자산의 SHA-256 검사를 통과했다.

## 실행 확인

- 다른 작업 폴더(`/tmp`)에서 `run.py sample --output <새 폴더>`를 실행했다. 번들 합성 사진에서 분할 → 3D 구성 → Blender 레이어 렌더 → 사진 합성을 완료했다. 모델과 5개 결과 PNG가 생성됐다. 이 환경에서 약 54초였으며 성능 보장은 아니다.
- 앞서 사용자가 제공한 원본 JPG도 이 저장소의 코드·새 가상환경에서 다시 처리했다. 원본 파일·마스크·수동 기준점은 저장소 밖에서 읽었고 커밋하지 않았다.
- 실사진의 입력 해시가 기존 처리 기록과 일치하고, 결과 전체 PNG가 기존 전달 파일과 바이트 단위로 일치했다.
- GLB는 메타데이터 JSON과 정점 속성이 같았다. 두 도식적 지방패드 구의 삼각형 인덱스 버퍼가 달라 **GLB 전체 바이트 동일성은 주장하지 않는다**. Blender의 구 메시 삼각분할에 따른 차이이며 PNG는 동일했다. 전달할 이미지와 모형은 각 실행에서 같은 GLB를 사용한다.
- `python -m unittest discover -s tests -q`: **24개 통과**. 외형 밖 픽셀 보존, API 확인 게이트·의견·삭제, 마스크 크기 검사, 자산 무결성, HTML에 내장된 GLB 바이트 일치 등을 포함한다.
- 뷰어: `npm ci && npm run build`로 번들 재빌드, `build_viewer.py`로 실행에서 생성된 GLB를 내장한 HTML을 생성했다. npm 소스·lock·버전·라이선스와 번들을 함께 포함했다.

## 검증하지 않은 것

Windows 실행, 실제 4카메라·수중 광학 보정, 개인 내부 복원, 임상 성능, 일반 시민 만족도를 검증한 것은 아니다. 실사진의 자세는 외부 기준점 4곳을 작업자가 지정했고, 자동 피부색 필터 대신 원래 U²-Netp 마스크를 확인해 선택했다. 이 수동 단계를 감춘 완전 자동 실사진 재구성으로 설명하면 안 된다.
